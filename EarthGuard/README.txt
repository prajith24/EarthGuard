==============================================================
 EARTHGUARD - POLLUTION PATTERN DETECTOR      Version 1.0
==============================================================

WHAT IT IS
EarthGuard is a menu-driven console program written only in C (C11).
You type in environmental readings (AQI, water pH, noise in dB). The
program validates them, saves them to a text file, classifies them with
documented project rules, compares locations, and flags unusual changes.

IMPORTANT: EarthGuard does NOT measure pollution. It analyses numbers
that a person enters. It is not a certified monitoring instrument.

FILES IN THIS FOLDER
  earthguard.c                 Complete source code (one file)
  pollution_data.txt           Saved records (created by the program)
  pollution_report.txt         Report (created by menu option 8)
  README.txt                   This file
  test_cases.txt               Test cases and the results actually observed
  project_report.txt           Report content for submission (all 26 sections)
  sample_data.txt              SAMPLE data (made-up values, see below)
  sample_pollution_report.txt  Report produced from the SAMPLE data

HOW TO COMPILE (Windows, GCC in a terminal opened in this folder)
  gcc -std=c11 -Wall -Wextra -pedantic -o earthguard.exe earthguard.c -lm

HOW TO RUN
  .\earthguard.exe          (PowerShell)     or     earthguard.exe  (cmd)

TRY THE SAMPLE DATA (optional)
  Copy sample_data.txt to pollution_data.txt before starting.
  The sample values are INVENTED for demonstration. They are not real
  measurements. Delete pollution_data.txt to start with your own data.

RECORD FORMAT (pollution_data.txt, one record per line, '|' separated)
  ID|Location|YYYY-MM-DD|AQI|pH|NoiseDB
  Example: 1|Model Town Ludhiana|2026-01-15|182|7.40|68.5
  Location names may contain spaces. The '|' character is not allowed
  inside a location. Do not edit this file by hand unless you keep the format.

INPUT RANGES (basic validation only - NOT safety limits)
  AQI    whole number 0-500   The illustrative scale used here ends at 500.
  pH     0-14                 The mathematical pH scale.
  Noise  0-200 dB             Rejects negatives and obvious typing mistakes.
  Date   real calendar date YYYY-MM-DD, year 1900-2100, leap years checked.
  Location 1-49 characters, printable characters, no '|'.
  Capacity 5000 records; a clear message appears when it is reached.

PROJECT ASSUMPTIONS (NOT official standards - change the #define values
at the top of earthguard.c to configure them)
  AQI categories (illustrative scale, not the official Indian AQI):
     0-50 Good | 51-100 Satisfactory | 101-200 Moderate |
     201-300 Poor | 301-400 Very Poor | 401-500 Severe
  Flag rule: AQI above 200.
  pH screening range: 6.5 to 8.5. Outside it = flagged for verification.
     pH alone cannot show water is safe or unsafe.
  Noise: up to 55 Low | to 70 Moderate | to 85 High | above 85 Very High
  Flag rule: noise above 70 dB. Impact depends on duration and setting.
  Change rules (flags for review, NOT proof of a pollution event):
     AQI change of 50 or more, noise change of 10 dB or more,
     pH change of 1.0 or more, or a reading newly crossing a flag rule.

FILE SAFETY
  - Adding a record appends one line; existing lines are never rewritten.
  - Sorting changes the order in memory only. The file changes only if you
    answer 'y' to the save question. Then a temporary file is written first.
  - Windows detail: rename() on Windows fails if the target file exists, so
    the program renames the old file to pollution_data.bak, moves the new
    file into place, and restores the backup if that fails.
  - Malformed lines (wrong fields, bad date, out-of-range value, duplicate
    ID, over-long line) are skipped and reported with line numbers. They
    are left in the file untouched.
  - If the data file cannot be read, EarthGuard says so; it never treats a
    read error as "no records".

KNOWN LIMITATIONS
  - Thresholds are simple project assumptions; compare with the official
    standard that applies in your region before drawing conclusions.
  - Maximum 5000 records. Location matching ignores upper/lower case.
  - Averages across places and dates can hide local conditions.
  - Tested on Linux with GCC 13.3. It has NOT been run on Windows by the
    author of this code; see test_cases.txt.
