2. ABSTRACT
-----------
EarthGuard is a menu-driven console application written in C. A user enters
air quality index (AQI), water pH and noise level (dB) readings for named
locations and dates. The program validates every entry, stores it in a text
file, classifies the values using documented project rules, compares two
locations, flags unusual changes between older and newer readings, and
creates a plain-text report. The program does not measure pollution; it
analyses manually entered data. All thresholds are project assumptions, not
official standards.

3. INTRODUCTION
---------------
Environmental readings are often kept in scattered notes. A small program
that stores them in one format, checks them for mistakes and highlights
changes helps students learn how data can be organised and analysed. The
project also practises core C topics: structures, dynamic memory, file
handling, string handling, sorting, searching and input validation.

4. PROBLEM STATEMENT
--------------------
Manually recorded pollution readings are easy to mistype, hard to compare
across locations, and hard to track over time. There is a need for a simple,
offline tool that validates entries, keeps a permanent record, and highlights
readings or changes that deserve a second look.

5. OBJECTIVES
-------------
- Accept and validate AQI, pH and noise readings with location and date.
- Store records permanently in a plain text file without a database.
- Classify readings using clearly documented project rules.
- Compare locations and detect changes over time for the same location.
- Search, sort and summarise records.
- Generate a text report with limitations and a disclaimer.
- Handle file and input errors safely, with no crashes.

6. SCOPE OF THE PROJECT
-----------------------
In scope: manual data entry, single-user console use, text-file storage,
up to 5000 records, three indicators (AQI, pH, noise).
Out of scope: live sensors, internet data, official compliance checking,
medical or legal advice, graphs, multi-user access, a database.

7. LIMITATIONS OF EXISTING SYSTEMS
----------------------------------
Paper notes and loose spreadsheets: no input validation, inconsistent date
formats, no automatic flagging, no standard report. Professional monitoring
systems: need instruments, licences and training, and are too complex for a
student-level, offline exercise.

8. PROPOSED SYSTEM
------------------
A single C program with 11 menu options. Records are held in a dynamic array
and saved in pollution_data.txt. Rules are constants at the top of the source
file, so they can be changed and recompiled.

9. HARDWARE AND SOFTWARE REQUIREMENTS
-------------------------------------
Hardware : any PC able to run Windows 10/11 (no special hardware).
Software : Windows, GCC (MinGW-w64 / MSYS2), Visual Studio Code with a
           terminal. No external libraries beyond the C standard library
           (math library linked with -lm).

10. FUNCTIONAL REQUIREMENTS
---------------------------
FR1 Add reading with generated unique ID, validated location/date/values.
FR2 View all saved readings in an aligned table with classifications.
FR3 Analyze a saved reading or typed-in values.
FR4 Compare two locations (values, differences, higher AQI and noise, pH check).
FR5 Detect unusual changes for each location in date order.
FR6 Search by ID, location text, or date.
FR7 Sort by location, date, AQI, pH or noise, ascending or descending.
FR8 Generate pollution_report.txt.
FR9 Show a summary dashboard.
FR10 Show project information.
FR11 Exit safely, freeing memory.

11. NON-FUNCTIONAL REQUIREMENTS
-------------------------------
Reliability: invalid input never changes saved data.
Safety: bounded input buffers, no gets(), no unbounded scanf("%s").
Usability: clear messages, retry after errors, readable tables.
Portability: standard C11; Windows-specific behaviour limited to file
replacement (explained in section 14).
Maintainability: thresholds are named constants; one function per task.
Privacy: no personal data is stored.

13. DATA STRUCTURE DESIGN
-------------------------
Record   : id (int), location (char[50]), date (char[11]), aqi (int),
           ph (double), noise (double).
Database : items (Record *), count, capacity - a dynamic array that grows
           by doubling, up to 5000.
LoadInfo : file missing flag, malformed-line count and numbers, truncation flag.
Stats    : totals, averages, maxima, pH minimum/maximum, flag counts.
Flags    : bit mask - 1 = AQI rule, 2 = pH rule, 4 = noise rule.

14. FILE STORAGE DESIGN
-----------------------
File: pollution_data.txt. One record per line:
   ID|Location|YYYY-MM-DD|AQI|pH|NoiseDB
The '|' separator is used instead of spaces so location names can contain
spaces. '|' is not allowed in a location. Each line is read with fgets()
into a fixed buffer, split by hand, and every field is validated; a line
that fails any check is reported as malformed and skipped, never deleted.
Adding a record appends one line. Rewriting happens only after sorting if
the user agrees: write pollution_data.tmp, then rename the old file to
pollution_data.bak, rename the temp file to pollution_data.txt, delete the
backup; if a step fails the backup is restored. (On Windows rename() cannot
replace an existing file, which is why this backup step is used.)

15. ALGORITHM
-------------
1. Start. Load records from the file; report missing file / bad lines.
2. Repeat:
   a. Show menu, read a line, convert to a number; if invalid show error.
   b. Run the chosen operation (add, view, analyze, compare, detect,
      search, sort, report, summary, info).
   c. Wait for Enter and return to step 2a.
3. When 11 is chosen, free memory, print closing message, stop.
Change detection: for each location, collect its records, sort by date (then
ID), and compare each neighbouring pair. Flag the pair if |dAQI| >= 50, or
|dNoise| >= 10 dB, or |dpH| >= 1.0, or a rule is newly crossed. Percentage
change is computed only when the old AQI is not zero.

19. STEP-BY-STEP WORKING PROCEDURE
----------------------------------
1. Compile the program and run earthguard.exe.
2. The program loads pollution_data.txt (or says no file exists yet).
3. Choose 1 to add readings: location, date, AQI, pH, noise. Each value is
   checked; errors explain the problem and ask again.
4. Choose 2 to see all records. Choose 3 to analyze one.
5. Choose 4 to compare two locations, 5 to look for unusual changes.
6. Choose 6 to search, 7 to sort (answer n to keep the file unchanged).
7. Choose 8 to create pollution_report.txt; 9 for the dashboard.
8. Choose 11 to exit. All saved records stay in the data file.

20. IMPORTANT C FUNCTIONS
-------------------------
readLine(buf,size)        Reads one line with fgets, removes newline/spaces,
                          discards extra characters if the line is too long.
promptLine/Int/Double     Repeat until valid; handle empty, too long, EOF.
validateNumericInput      strtod with end-pointer check; rejects text, NaN,
                          infinity and out-of-range numbers.
isLeapYear/validateDate   Divisible by 4 and not by 100, or by 400; checks
                          month lengths.
classifyAQI/PH/Noise      Return the category text for a value.
flagMask                  Bit mask of the screening rules a record crosses.
loadRecords/parseRecordLine Read and fully validate the data file.
appendRecordToFile        Appends one line; checks fopen, fprintf, fclose.
saveRecords               Temp file + backup + rename (safe rewrite).
analyzeChanges            Date-ordered comparison per location; writes to any
                          FILE* so the screen and the report share one code path.
computeStats              Totals, averages, maxima, flag counts; safe when empty.
compareRecords            qsort comparator for the five sort keys.
freeResources             Frees the dynamic array.

23. LIMITATIONS
---------------
- Does not measure pollution; relies on correct manual entry.
- AQI scale, pH range and noise limits are project assumptions, not official.
- pH alone does not decide water safety; noise impact depends on duration.
- Fixed capacity of 5000 records; one user; no graphs.
- Location names are matched by text, so spelling differences make separate locations.
- Change flags are rules for review, not proof of a pollution event.
